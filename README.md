# Proposal Portal Astra

정보시스템 감리 제안팀의 인력·사업 조회, 본문 PPT 및 첨부서류 제작 포털입니다.

## 실행 환경과 연결 대상

- GitHub: https://github.com/sweatmoon/proposal-portal-astra
- Astra 운영 주소: https://proposal-portal-proposal-portal-astra.up.railway.app/
- Hono + Node.js + PostgreSQL, Docker/Railway 배포
- 사진·회사 증빙·인력 서류는 Synology NAS에서 조회
- Cloudflare 초기 파일이 남아 있지만 현재 실행 대상은 Node.js입니다.
- 승인된 변경만 Astra GitHub main에 푸시합니다. GitHub 푸시 성공과 Railway 배포 완료는 별개이며, 이번 작업에서 Railway 배포 상태 조회는 제외합니다.
- 운영 DB 및 원본 `sweatmoon/proposal-portal`은 변경하지 않습니다.

## 주요 경로

- `/`: 현황 대시보드
- `/proposals`, `/proposals/:id`: 사업 목록·상세, 본문 PPT 모달
- `/personnel`, `/personnel/:id`: 인력·경력 조회
- `/upload`: HTML 적재
- `/ppt-templates`: 목차·템플릿 관리
- `/ppt-generate`: 첨부서류 생성
- `/api/ppt-menus?category=proposal`: 본문 목차·템플릿 조회
- `/api/ppt-menus/master-templates/active`: 활성 마스터 조회
- `POST /api/personnel/photo-images`: 읽기 전용 사진 일괄 조회, JSON `{ "names": ["이름"] }`, 요청당 1~100명
- `GET /api/personnel/photo-image-by-name?name=이름`: 이름 기반 사진 조회
- `GET /api/personnel/:id/photo-image`: ID 기반 사진 조회
- `/health`: 서버 상태

## 인력 HTML 업로드 → 기존 사업 인력 자동 갱신 및 이름/(K) 연결

- `POST /api/upload/personnel`에서 인력을 저장한 뒤, **같은 트랜잭션**으로 등록된 모든 사업(진행/완료 구분 없음)의 해당 인력을 동기화합니다. DB 직접 일괄 보정이나 마이그레이션은 수행하지 않았으며, 배포 후 인력 HTML을 다시 업로드할 때 실행됩니다.
- 사업 인력 `proposal_members`의 자동 갱신 허용 목록은 **`auditor_grade`, `auditor_cert_no`, `phone`, `education_hours` 4개뿐**입니다. HTML에서 명확히 파싱된 값만 사용합니다. 누락/빈값/미등록 표기는 기존 값을 유지하고, 교육시간은 실제 `0`과 누락 기본값 `0`을 구분합니다. 잘못된 시간 범위/음수/비숫자를 임의 숫자로 전파하지 않습니다. 인력 마스터의 이 4개 필드도 재업로드 누락 시 기존 값을 보존합니다.
- **사업 상근/비상근(`proposal_members.is_fulltime`)은 항상 사업 HTML 기준으로 유지합니다.** 인력 HTML의 상근/비상근으로 덮어쓰지 않습니다. 인력 마스터 자체의 파싱은 `비상근`을 `상근` 부분 문자열로 잘못 읽지 않도록 구분하지만 사업 동기화 허용 목록에는 들어가지 않습니다.
- 사업명/사업 ID/주관기관/금액/요구조건/사업 상태, 인력명/팀/구분/역할/분야/공수/산출 공수/단계/일정/배정/생성 시각은 변경하지 않습니다. `audit_projects`, `audit_phases`, `audit_phase_assignments` 등 사업 테이블을 수정하지 않으며 사업 인력행을 삭제하거나 재삽입하지 않습니다.
- 기존 `personnel_id`와 이름이 일치하는 인력행은 공통값을 갱신합니다. 연결 ID가 NULL이면 앞뒤 공백을 제외한 정확한 이름 일치가 인력 DB에서 유일할 때만 ID를 채웁니다. 부분 이름/약칭 추정, 이미 다른 인력에 연결된 ID의 덮어쓰기, 이름 불일치/모호한 동명이인의 임의 연결은 하지 않습니다. 제외 건수와 사유를 반환합니다.
- ID가 연결되면 기존 사업 상세 렌더링에 의해 이름 상세 링크와 **`김현호 (K)`** 형식의 키워드/이력 조회 링크가 함께 표시됩니다. 열려 있는 사업 상세는 새로고침하거나 다시 열어야 합니다. 사업 인력명 자체는 변경하지 않습니다.
- 응답 `data.profile_sync`에 매칭/실제 변경 인력행 수, 변경 사업 수, 신규 연결 수, 연결 검토 제외 수, 제공된 갱신 필드 목록과 경고를 담습니다. `/upload` 결과에도 변경·연결·검토 건수와 사업 상근/비상근 보존 안내를 표시합니다. 동일값 재업로드는 변경 건수 0입니다.
- 인력·이력 저장과 사업 인력 동기화 중 하나라도 실패하면 모두 롤백합니다. 인력 이력 테이블의 기존 삭제 후 재적재 방식은 유지합니다. 이후 사업 HTML을 다시 업로드하는 기존 사업 적재 동작 자체는 변경하지 않았습니다.
- 테스트용 PGlite는 devDependency이며 데이터 디렉터리 없는 메모리 PostgreSQL로만 실행됩니다. 별도 서버/운영 연결/운영 SQL 실행은 없습니다. 테스트에서 보호 필드 변경을 거부하는 트리거와 전체 값 비교를 사용해 상근/비상근(1/0/NULL), 두 사업의 공수·금액·일정·단계·배정 보존, 롤백, 모호한 이름/연결 충돌, 신규 이름/(K) 링크 SSR을 검증했습니다. 운영 적용 여부는 별도 배포 후 확인이 필요합니다.

## 제안작업표 감리 요구사항 표시

- `/proposals/:id` 기본 정보 아래 `감리 요구사항` 영역에서 저장된 요구 단계·요구 감리 일수·요구 투입 공수를 함께 표시합니다.
- `required_phases`, `required_audit_days`, `required_md`를 각각 단계·일·MD 단위로 표시하며 실제 배정 단계/공수로 대신 계산하지 않습니다.
- 값이 없으면 `미입력`, 0이면 `0 단계`/`0 일`/`0 MD`로 구분합니다. PostgreSQL 숫자 문자열과 소수도 표시합니다.
- 기존 금액 정보의 요구투입공수는 이 영역으로 이동했으며 제안투입공수는 그대로 유지합니다.
- 이번 변경은 화면 표시만 추가합니다. HTML 파싱·DB 스키마·저장값 및 PPT 생성 데이터는 변경하지 않습니다.

## 본문 PPT 기능

- 모달의 `개별 생성` 영역 및 세부 일정·표장표·사진장표·요약표 4개 버튼을 제거했습니다. 전체 합본 생성 버튼과 사진 분류 설정은 유지합니다. 개별 일정/요약표 다운로드 전용 함수를 제거하고 표/사진 공용 함수는 파일 다운로드 없이 ZIP을 합본 엔진에 반환합니다. 일정·3.6·사진 슬롯·실적·합본 보고서 공용 엔진은 유지합니다.

- `public/static/proposal-template.js`: 본문 전용 XML 치환·계산·검증
- 분산 런·반복 토큰·XML 특수문자·원본 서식 처리
- 사업명·주관기관·대상사업명·기간 전달, 인력별 배정 MD 합산
- 공통/일정의 `[요구감리일수]`는 화면과 같은 저장 요구값(`required_audit_days` → `requestAuditDays`)을 숫자만 치환합니다. `[요구감리일수]일`은 저장값 5일일 때 `5일`로 표시하며 실제 단계 일수나 고정 5로 대체하지 않습니다. 공백·분산 런 토큰, 숫자 문자열·소수·0을 지원하고 누락·음수·비숫자는 미치환 경고로 남깁니다. 3.6의 기존 미입력 표시 정책은 유지합니다.
- 제목·주관기관만 사용하는 일반 장표에 공수 경고를 붙이지 않음. 실제 공수표/공수 토큰에만 적용
- 감리 일정 계획: 단계·분야 행, 전체 기간의 월 열·연도 병합, 날짜 막대를 동적으로 생성
- 세부 감리 일정: 단계별 활동 블록과 상주/상시·검수지원 블록을 실제 개수대로 복제
- 일정표의 표시 글자 크기는 원본 유지. 자동 축소와 페이지 추가 없음. 여백·들여쓰기·표 폭·행 높이·위치를 조정하며 빈 셀의 비표시 문단도 정리
- 좁은 세부 일정 요약 도식에는 종류별 단계 수를 표시. 전체 단계명·날짜는 왼쪽 본표에서 유지
- 대상사업 기간이 `2026.09` 같은 월 단위이면 그대로 치환. 월 경계는 일정 도식 배치에만 사용하고 표시 날짜에 임의 일자를 추가하지 않음
- 조치확인 표: `post > 0`인 인력이 있는 단계만 열로 생성. 인력은 실제 참여자 수만큼 행을 생성하며 3단계/15명 제한 제거
- 단계별 참여 이름·post 합계, 수행방안 및 활동/시기 병합 셀을 새 행·열 개수에 맞춤. 대상이 없으면 대상 없음 표시
- 조치확인 장표의 투입 공수는 해당 단계 참여자의 `post` 합계입니다. 전체 `pre+audit+post` 합계나 사업 제안공수와 비교하지 않으며, `ACTION_CONFIRM_STAFF`에는 사업 전체 제안공수 불일치 경고를 전달하지 않습니다. 잘못된 배정값·인력 목록 누락·미치환 및 수행방안/횟수 검토 경고는 유지하고, 다른 전체 공수 검증은 변경하지 않습니다.
- 조치확인 주요 수행방안은 원본 셀을 복제하고 병합 범위만 조정. `txBody`/`tcPr`를 보존하여 색상·강조·글머리표·명시적 줄바꿈·빈 문단·들여쓰기·셀 여백을 평탄화하지 않음
- 조치확인 왼쪽 분류는 실제 분야 기준: 사업관리/품질보증 → 응용시스템(하위 분야) → 데이터베이스 → 시스템 구조 및 보안. 응용시스템 상위 셀은 세로 병합, 나머지 분야는 두 분류 칸을 가로 병합. 실제 분야명과 괄호의 사업 구분은 유지
- 분야 판별은 사업관리/품질보증·DB/데이터베이스·시스템구조 등 명시적 명칭 우선. 나머지 감리원 분야는 응용시스템 하위로 표시하며, 그 외 전문가는 해당 분야명을 그대로 표시. 분야 누락은 확인 필요로 표시. 분류 내 기존 인력 순서와 단계별 이름 대응은 유지
- 일부 목차 실패나 경고가 있어도 생성된 장표는 확인창 없이 다운로드. 전부 실패/합본 실패는 오류 표시
- 사진 장표의 기존 2/4/6/9인 슬롯·인력 순서·페이지 복제 유지
- 3.1/3.2/3.3 공용 사진 생성기: 이미지 관계 ID는 한 번만 치환. 공유 rId의 첫 객체를 임의로 바꾸는 fallback을 제거하고 선택된 사진 DOM 객체만 교체
- 장표 밖 우측·하단 예시 그림은 슬롯 귀속 및 빈 슬롯 삭제에서 제외. 사진은 장표 안 이름 플레이스홀더에 인접한 단일 증명사진 후보만 선택
- 사진 객체 누락·중복이나 좌표가 불확실한 그룹 내부 사진은 다른 로고로 대체하지 않음. 기존 사진 없음/TBD 기본 이미지 정책은 유지. 새 양식을 등록할 때에는 이름-사진 배치 및 그룹 구조를 검증해야 함
- RFP 공수는 전체 인력 합계, 일수는 각 기본 일반단계별 최소 기준으로 자동 비교. 요구값·배정값 누락 시 충족을 확정하지 않으며 인력 자격은 증빙 검토 필요
- 합본의 미디어 ContentType·외부 링크 보존, 마스터 ID 충돌 방지
- 3.4 감리원·3.5 전문가 실적 장표: 삭제 전에 원본 슬라이드 `.rels`를 확보하고 모든 복제 페이지에 그대로 사용. 그림의 원본 rId·외부 링크 TargetMode·레이아웃 연결 및 우측 작업용 예시 객체를 보존

- 수행 PM 선택은 유지합니다. 선택은 생성 시 브라우저 입력이며 DB에 저장하지 않습니다.
- 숫자 비교용 기본 단계는 추가 선택 단계 및 상시/상주/검수지원 제외입니다. 일정 목록은 보조·추가 단계를 포함해 모두 표시합니다. 단계 명칭/감리 방법의 RFP 대응 여부는 담당자가 확인해야 합니다.
- 전체·기본/추가 감리원·전문가·테스터 MD는 실제 배정값으로 계산합니다. 요구 대비 비율도 전체 인력 MD 합계로 계산합니다. 원본 누락 값(null→0), 잘못된 배정값, 저장 제안 MD 불일치, 배정 없음은 검토 필요입니다.
- `fulltimeKnown`과 `mdComplete`를 SSR JSON에 추가하여 미확정 상근값 및 원본 공수 누락을 구별합니다. 기존 숫자와 사진용 residency 표시를 바꾸거나 DB/파서를 변경하지 않습니다.
- 감리원 인원·수석 표기·상근 비율·분야, 핵심/필수/보안/기타 전문가 및 테스트 인원·분야는 양의 유효 공수가 있는 배정 인력을 중복 제거해 표시합니다. 상근 여부 미확인 시 비율을 확정하지 않습니다.

- 총괄 수행 건수·감리 경력·전체 감리 건수는 선택한 PM의 인력 DB에서 자동 조회합니다. `GET /api/personnel/:id/compliance-profile?projectId=N`은 해당 사업과 인력 ID 연결을 확인한 뒤 `personnel` 및 `personnel_audit_history`를 SELECT만 합니다. NAS/운영 DB 쓰기/마이그레이션은 없습니다.
- 총괄 건수는 감리이력 `role`의 총괄·총괄감리원·감리총괄·총괄책임자·PM 등 명시된 역할을 집계합니다. 부총괄/비총괄/총괄보조는 포함하지 않습니다. 전체 건수는 인력정보와 같은 이력 행 수이며 사업명으로 중복 제거하지 않습니다. 역할 누락은 보고서에 알립니다.

## 라.3.6 계속교육 및 마.3.5 안전·보건

- `CONTINUING_EDU`와 `SAFETY_HEALTH`를 전용 생성기에 연결했습니다. 실행 시 등록된 DEFAULT(없으면 첫 유효) 양식을 사용하며 코드의 참고 PPT로 대체하지 않습니다.
- 대상은 일반 감리 단계에서 pre/audit/post 중 확인된 양의 공수가 있는 단계감리원입니다. 추가 일반단계는 포함하며 전문가·테스터·미배정 및 상주/상시/검수지원에만 배정된 인력은 제외합니다. 제안 인력 순서로 중복 제거하고 선택한 유효 PM을 맨 앞에 놓습니다. 부분 공수 누락이 있어도 확인된 양의 배정 인력은 유지하고 명단 검토 경고를 남깁니다.
- `GET /api/personnel/:id/education-profile?projectId=N`: 해당 사업의 인력 ID 연결을 확인한 뒤 `personnel.education_name`, `education_hours`, `education_org`만 SELECT합니다. 사업 인력의 복사된 교육시간·NAS 자료는 사용하지 않습니다. 양의 정수 ID 검증, SQL 파라미터 바인딩, no-store 응답, 조회 실패 시 일반화된 503 오류를 사용합니다. 스키마/파서/운영 데이터 쓰기는 없습니다.
- 계속교육 표는 등록 양식의 `[이름N]`, `[교육명]`, `[교육시간]`, `[교육기관]`이 있는 연속 인력 행만 복제·삭제합니다. 현재 실양식은 헤더 1행 + 인력 7행입니다. 인원이 적으면 남는 인력 행을 삭제하고, 많으면 원본 행 서식으로 확장해 기존 인력 영역 높이를 나눕니다. 글꼴·표 폭·문단·색상은 유지하며 세로 병합 등 안전하게 확장할 수 없는 구조는 오류로 알립니다.

## 3.7 감리원 및 전문가 투입 비율

- `MANPOWER_RATIO`를 전용 등록 양식 생성기에 연결했습니다. DEFAULT(없으면 첫 유효) PPTX를 사용하며, 등록 파일 자체를 변경하거나 참고 양식으로 대체하지 않습니다. 원본 한 장 구조를 사용하고 양식 없음/잘못된 슬라이드 구조는 명시적으로 실패합니다.
- `[단계1]`부터 단계 순서대로 `[A1]` 감리원 MD, `[B1]` 전문가·테스터 MD, `[C1]` 전체 MD를 채웁니다. 각 인력의 `pre+audit+post`를 합산하며 캐시된 그룹 total이나 사업 제안 MD로 대체하지 않습니다. 추가·상시·상주·검수지원 단계도 포함합니다.
- `[A]`, `[B]`, `[C]`는 전체 단계의 각 합계, `[PA]`는 A/C, `[PB]`는 B/C의 백분율입니다. `%`는 양식에 남겨 숫자만 넣고 소수 둘째 자리까지 표시합니다. 전문가 버킷에 테스터가 포함되는 현재 데이터 구조를 보고서에 명시하며 법적 전문가 인정 범위는 별도 검토합니다.
- 빈 인력 버킷은 0MD, 원본 누락(`mdComplete=false` 포함)·음수·비숫자는 미확인입니다. 데이터 없음 또는 C=0이면 비율을 0%나 충족으로 확정하지 않습니다.
- `[판정]`은 등록 양식의 `전문가 비율 (N% 범위내/이내)` 문구에서 명시된 상한을 확인했을 때만 `N% 이내/초과`로 치환합니다. 반올림 전 비율로 비교하며 법령/RFP 준수를 단정하지 않습니다. 상한을 확인하지 못하면 검토 필요입니다. 배치기준 검토/요약·비율검토 문구 토큰도 연결했습니다.
- 모든 토큰은 선택 사항입니다. 토큰 없는 고정 제목·판정·문구는 그대로 두며, 실제 존재하는 미지원 토큰만 미치환 경고를 표시합니다. 장표 밖 참고 객체, 이미지·관계 파일, 원본 글꼴·색상·문단·표 병합을 보존합니다.
- 4개 미만 단계의 남은 슬롯은 빈 값으로 치환합니다. 4개 초과는 연속 단계 행을 복제해 기존 단계 영역 높이에 배치하며 우측 비율 열의 세로 병합을 확장합니다. 글꼴 축소/페이지 추가 없이 모든 단계를 표시하고 배치 검토 경고를 남깁니다. 안전하게 확장할 수 없는 구조는 일부 단계만 누락하지 않고 실패합니다.
- `전문가비율막대_PB_높이연동대상` 도형과 `기준비율막대_30퍼센트`를 식별하고 `전문가비율라벨_PB`에 `[PB]`가 있을 때만 그래프를 연동합니다. 0~30% 구간은 기준 막대 높이에 비례해 하단을 고정하고 라벨을 함께 이동합니다. 소수 비율이 줄바꿈되지 않도록 연동 라벨 폭만 확보하고 원본 폰트는 유지합니다.
- 비율 미확인/30% 초과는 고정 축을 임의 수정하거나 30%로 잘라 그리지 않고 연동 막대를 숨깁니다. 표·라벨에 실제 비율 또는 미확인을 표시하며 보고서에 사유를 알립니다. 도형 이름/라벨 토큰이 없거나 중복이면 임의의 그림을 변경하지 않고 경고합니다.
- 제공된 3.7 플레이스홀더 양식으로 4단계·6단계·30% 초과·미입력 사례를 LibreOffice PDF로 렌더링하여 각 1장, 모든 단계/합계 표시 및 비율 라벨 줄바꿈 해소를 확인했습니다. 운영 등록 파일을 다시 조회하거나 DB/NAS에 접근하지 않았으며 Windows PowerPoint 직접 검수는 아닙니다.

## 활동별 일수·공수 계산

입력 순서는 `예비조사(pre) : 감리시행(audit) : 사후관리(post)`입니다.

- 활동별 MD: 감리원별 해당 값을 합산
- 활동별 일수: 동일 활동의 병행 수행을 전제로 감리원별 해당 값의 최댓값 사용
- 소계 일수: 예비조사 일수 + 감리시행 일수 + 사후관리 일수
- 소계 MD: 세 활동의 MD 합산
- 누락·음수·비숫자 입력은 확인 필요 표시. 빈 값이나 잘못된 값을 정상적인 0으로 확정하지 않음
- 별도 달력에 인원별 순차 근무가 정의되는 업무에는 이 병행 수행 규칙을 그대로 적용할 수 없으므로 추가 규칙 확정 필요

사용자 확인 사례: 1명이 `1:5:1`, 나머지 4명이 `0:5:1`이면:

| 활동 | 일수 | 공수 |
|---|---:|---:|

## 사진 조회 및 데이터

- NAS 사진은 이름 기반 일괄 조회, 요청당 로그인 한 번, 최대 3개 동시 다운로드
- 이름 조회 라우트 충돌 해결, ID=0 인력도 구분, TBD는 조회 제외
- 인증·권한·네트워크 오류와 파일/경로 없음을 구분, PNG 시그니처 검사
- 이전 사진 슬롯 수정은 브라우저 생성기에 한정했습니다. 후속 요청으로 사진·주관기관 로고의 NAS 로그인/조회/다운로드 제한을 요청당 15초에서 60초로 확대했습니다. 로그아웃은 10초이며 브라우저 사진 fetch에는 별도 짧은 시간 제한이 없습니다.
- 시간 초과(`nas_timeout`)와 연결 실패(`nas_connection_error`)를 구분합니다. 시간 초과·연결 실패·일시 HTTP 408/429/502/503/504·세션 오류 106/107/119만 최대 한 번 재시도합니다. 성공한 사진은 유지하며 권한/파일 없음 오류는 재시도하지 않습니다. 재로그인을 포함해 전체 처리는 60초보다 길 수 있습니다.
- 모의 NAS 테스트로 제한값·실패 인력만 재시도·성공 사진 보존을 검증했습니다. 단계감리원 사진만 실패한 운영 원인은 확정하지 않았으며 실제 NAS 연결 성공을 확인한 것은 아닙니다. NAS 설정·권한 변경이나 추가 운영 진단은 하지 않았습니다.
- PostgreSQL에 인력·경력·사업·단계 배정·템플릿·규칙 저장. 신규 DB 마이그레이션 없음
- `DATABASE_URL`, `NAS_BASE_URL`, `NAS_USERNAME`, `NAS_PASSWORD`는 Railway Variables 또는 로컬 `.env`에서 관리하며 커밋하지 않습니다.
- 사용자에게서 확인된 운영 DB 스키마를 변경하거나 저장소의 구형 schema로 재생성하지 마세요.

## 사용 방법

1. 인력·사업 HTML 적재 후 사업 상세의 자동화 PPT 모달을 엽니다.
2. 추가 단계·사진 구성을 선택합니다. 3.6은 등록된 사용자 양식을 사용하고 수행 PM을 선택합니다. 공수·일수 비교 기준은 자동 적용됩니다.
3. 생성 버튼을 누르면 검토용 PPT가 바로 다운로드됩니다.
4. 생성 보고서와 실제 장표의 날짜·공수·참여 인력·배치를 확인합니다.
5. 원본 폰트를 유지하므로 데이터가 물리적 공간을 초과하면 배치 검토 경고가 표시됩니다. 조용히 글자를 줄이거나 데이터를 누락하지 않습니다.

## 본문 PPT 생성 보고서 화면

- 자동화 PPT 모달은 최대 1,120px, 화면 높이의 92%까지 사용합니다. 모바일(640px 이하)은 작은 여백과 세로 배치를 사용합니다.
- 등록된 메뉴의 `parent_id`/`children` 계층과 `menu_number`를 사용해 다·라·마·바 등의 상위 목차별로 결과를 구분합니다. 보고서의 항목 번호는 `라.3.7`, `마.3.6`처럼 표시하며 제목에 이미 있는 중복 번호는 표시에서만 제거합니다.
- 상위 목차는 접기/펼치기가 가능하고, 같은 생성 작업의 진행 갱신 중에도 접힌 상태를 유지합니다. 새 생성 작업에서는 기본 펼침 상태로 시작합니다.
- 상단에 처리 목차 수·생성 장수·생성됨/검토 필요/생성 실패/생성 중 개수를 표시합니다. 항목별 상태 배지와 장수, 상위 목차별 실패/검토 개수를 표시합니다.
- 경고는 항목 아래 별도 목록으로 한 줄씩 표시합니다. 중복 문구만 제거하고 미치환 토큰·오류 원문을 잘라내지 않습니다. 공통 안내는 마지막 별도 영역에 표시합니다. 텍스트는 `textContent`로 렌더링합니다.
- 단독 3.6 및 선택 목차 생성에도 같은 보고서 형식을 적용합니다. 번호/상위 목차가 없으면 임의 번호를 붙이지 않고 번호 미등록/기타 목차로 표시합니다.
- 보고서용 메타데이터·표시만 변경하며 원본 메뉴/템플릿·PPT 생성 로직·합본 순서·부분 다운로드 정책·DB/NAS는 변경하지 않습니다. 기존 생성 실패/미치환 문제를 이 UI 변경으로 해결한 것은 아닙니다.
- 로컬 Chromium에서 실제 Hono SSR(모의 DB) 모달에 예시 생성 로그를 넣어 1,440px 화면의 1,120px 모달, 390px/320px 모바일의 가로 넘침 없음, 긴 경고 줄바꿈, 키보드 접기/펼치기와 갱신 시 상태 보존을 확인했습니다. 운영 DB/NAS 및 외부 페이지 요청은 사용하지 않았습니다.

## 첨부 및 서류 생성 진행·상세 결과 모달

- `/ppt-generate`의 사업 기반 및 자유 첨부 생성에 공통 모달을 적용했습니다. 기존 항목 선택·키워드·인력·도장·날짜 옵션 전달과 생성 순서는 유지합니다. 생성 버튼을 누르면 준비/전송 → 항목별 조회·생성 → 표지 → 합본/압축 → 파일 수신·다운로드 요청을 표시합니다.
- 각 항목은 대기/처리 중/생성 완료/검토 필요/실패/미처리로 구분합니다. 항목을 펼치면 장수·인원수·기존 상세 설명·제외 인력을 확인할 수 있습니다. 진행 막대는 표지를 포함한 항목 생성 완료 수이며 합본·다운로드 상태는 별도 행입니다. 임의 시간 기반 퍼센트는 사용하지 않습니다.
- `POST /api/ppt-attachment-bundle/:projectId`에 `Accept: application/x-attachment-progress`를 보내면 실제 처리 경계의 줄 단위 JSON 이벤트(`ready/start/item/error/file`)와 이어지는 원본 PPTX 바이트를 한 응답으로 받습니다. `file.size`를 검증하고 전체 수신 후에만 다운로드를 요청합니다. 별도 작업 ID/저장소/폴링/백그라운드 작업/DB 쓰기는 없습니다. 헤더가 없는 기존 호출의 PPTX 바이너리와 `X-Bundle-Summary` 응답은 유지합니다.
- 장수는 생성 ZIP의 실제 presentation 슬라이드 목록에서 계산합니다. 경력서 1페이지 모드나 여러 페이지 증명서, 여러 장 표지를 인원수 기반 추정치로 보고하지 않습니다. 자격증사본은 실제 장표를 포함한 인원 수를 표시합니다.
- 자격증사본·경력증명서는 생성기에서 실제 확인한 인력별 포함 장수/제외 결과를 반환합니다. 빈 자격증 PPTX는 슬라이드 없음으로 구분합니다. 기존 NAS 함수가 자료 미발견과 개별 조회 실패를 구분하지 않는 경우 원인 미확정을 명시하며 추정하지 않습니다. 다른 항목은 제공되는 인원수·제외 목록까지만 표시합니다. 인력 한 명씩의 실시간 NAS 진행률은 제공하지 않습니다.
- 기존 첨부 생성기의 오류 시 중단 정책을 유지합니다. 앞서 완료된 항목의 보고서는 남기고 실패 항목과 뒤의 미처리 항목을 구분하며, 자동 재요청이나 실패한 합본 다운로드는 하지 않습니다. 본문 PPT의 부분 성공 합본 정책을 첨부 쪽에 임의 적용하지 않았습니다. 미지원 선택 항목은 보고서에 미처리 사유를 표시합니다.
- 파일 수신 완료 후 브라우저에 다운로드를 요청하며 실제 디스크 저장 완료라고 단정하지 않습니다. 완료 모달은 유지되고 같은 파일 다시 다운로드는 서버 재생성 없이 Blob을 사용합니다. 새 작업 시작 시 이전 다운로드 URL을 해제합니다.
- 작업 중 닫기는 취소가 아닙니다. 같은 페이지의 `첨부 진행·결과 보기` 버튼으로 다시 열 수 있고 사업/자유 경로 간 중복 실행을 방지합니다. 새로고침/페이지 이동에는 브라우저 확인을 요청하며 결과는 현재 페이지에서만 유지됩니다. 키보드 포커스 순환·Escape·닫기 후 포커스 복귀 및 긴 문구 줄바꿈을 지원합니다. 동적 오류/이름은 textContent로 표시합니다.
- 모의 API·NAS를 사용한 자동 테스트와 로컬 Chromium으로 두 생성 경로, 항목 진행 이벤트, 중복 방지, 누락 내역, 실패/파일 수신 중단, 다시 다운로드, 닫기/재열기, 키보드 및 1440px·390px·320px 화면을 검증했습니다. 운영 DB/NAS 호출·설정 변경·등록 템플릿 변경·Railway 조회는 하지 않았습니다. 운영 프록시의 스트림 전달 및 실제 서류 생성은 배포 후 사용자 확인이 필요합니다.

## 첨부 전용 마스터 등록·사업명·주관기관 로고

- `/ppt-templates` → **첨부** 탭 → **첨부 마스터 템플릿**에서 사용자가 PPTX를 등록하고 활성화합니다. 이번 기준 원본은 `제안서첨부_마스터.pptx`(46,040 bytes, SHA256 `61a7fa4e6d078893a429adcfc4afd5a04dda32eb44192dcc95c341e3abc70d92`)이며 `artifacts/attachment_user_master.pptx`는 테스트용 사본입니다. 운영 등록이나 자동 fixture fallback은 하지 않습니다.
- 기존 `/api/ppt-menus/master-templates` 목록·등록·`/active`·`/:id/activate`·`/:id` 삭제 API에 `?category=attachment`를 사용합니다. 생략하면 기존 `proposal`입니다. 목록·활성화·삭제가 구분별로 제한되며, 잘못된 구분/다른 구분의 ID는 거부합니다. 등록 검증 후 동일 구분 활성 전환을 트랜잭션/잠금으로 수행해 본문 활성 마스터에 영향을 주지 않습니다.
- 스키마 변경 없이 기존 `ppt_master_templates.layouts` JSONB를 사용합니다. 기존 레이아웃 이름 배열은 본문용으로 유지하고 신규 첨부 행은 `{scope:'attachment', names:[...]}` 메타데이터를 저장합니다. API는 두 경우 모두 `layouts` 배열로 정규화합니다. 기존 등록 행을 일괄 수정하지 않습니다.

- `src/lib/pptx-attachment-master.ts`는 등록 마스터를 합본 기준 ZIP으로 사용하고 표본 슬라이드는 합본 목록에 넣지 않습니다. 원본 각 첨부의 참조 파일을 충돌 없는 이름으로 복사하고 part별 관계를 재연결합니다. 이미지·외부 하이퍼링크·ContentType을 보존하며, 원본 레이아웃 번호를 새 마스터에 임의 대응시키지 않습니다. 크기 불일치/참조 누락/잘못된 활성 파일은 오류이며 자동 축소·내용 삭제·구형 합본으로 조용히 대체하지 않습니다.
- 생성 요청은 **첨부용 활성 마스터만 SELECT**합니다. 마스터/레이아웃의 실제 `[감리사업명]`(분산 런 포함)은 저장된 `audit_projects.project_name`으로 치환합니다. 저장된 `client_org`로 기존 지정 NAS 폴더의 로고를 한 번 조회합니다. 인력사진·도장·고정 문구를 변경하지 않습니다.
- 빨간 안내 그림은 원본 이미지 SHA256 또는 명시적 `주관기관 로고` 그림 이름/설명으로 식별합니다. 새 관계와 이미지 파일을 추가해 그 그림만 교체하고 기존 그림 파일 및 ACTIVO 회사 로고는 보존합니다. 원래 박스 안에서 종횡비를 유지합니다. 로고 미발견/중복/시간 초과/형식 오류는 안내 그림을 유지하고 보고서에 경고합니다.
- 자유 생성(projectId=0)은 저장 사업명/주관기관이 없어 이름·기관을 추정하지 않습니다. 토큰/로고 안내 그림을 유지하고 경고하며 NAS 로고 요청을 하지 않습니다. 활성 첨부 마스터가 없으면 기존 표지 내장 마스터 사용 사실을 보고서에 표시합니다. 활성 마스터 조회/준비가 실패한 경우는 생성 실패입니다.
- 진행 모달에 `첨부 마스터·사업명·주관기관 로고` 준비 행을 추가했습니다. 적용할 마스터 이름과 미치환 경고를 확인할 수 있습니다. 로고 경고가 있어도 생성 가능한 합본은 받을 수 있고 실제 합본 오류는 실패로 표시합니다.
- 실제 제공 마스터에 시험 본문/사업명/TEST CLIENT 로고를 넣은 2장 결과를 LibreOffice로 렌더링해 내용 장표의 사업명·왼쪽 로고·오른쪽 ACTIVO 보존을 확인했습니다. 합성 본문을 표지 장식 중앙에 놓은 시험 결과의 겹침은 실제 등록 표지의 배치 검증이 아닙니다. ## 첨부 자격증사본 이미지 ContentType 보존 수정
