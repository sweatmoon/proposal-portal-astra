# Proposal Portal Astra

정보시스템 감리 제안팀의 인력·사업 조회, 본문 PPT 및 첨부서류 제작을 지원합니다.

## 실행 환경과 연결 대상

- GitHub: https://github.com/sweatmoon/proposal-portal-astra
- Astra 운영 주소: https://proposal-portal-proposal-portal-astra.up.railway.app/
- Hono + Node.js + PostgreSQL, Docker/Railway 배포
- 사진·회사 증빙·인력 서류는 Synology NAS에서 조회
- Cloudflare 관련 초기 파일이 남아 있으나 현재 실행 대상은 Node.js입니다.
- 사진 조회 및 다운로드 확인창 제거 `3e2c8db`까지 GitHub에 푸시했습니다.
- 이번 일정표 단일 장 확장·장표별 경고 범위 수정은 로컬 검증 단계입니다. 운영 반영은 별도입니다.
- 운영 DB 및 원본 저장소는 변경하지 않습니다.

## 주요 경로

- `/`: 현황 대시보드
- `/proposals`, `/proposals/:id`: 사업 목록·상세, 본문 PPT 모달
- `/personnel`, `/personnel/:id`: 인력·경력 조회
- `/upload`: HTML 적재
- `/ppt-templates`: 목차·템플릿 관리
- `/ppt-generate`: 첨부서류 생성
- `/api/ppt-menus?category=proposal`: 본문 목차·등록 템플릿 조회
- `/api/ppt-menus/master-templates/active`: 활성 마스터 조회
- `POST /api/personnel/photo-images`: 읽기 전용 사진 일괄 조회, JSON `{ "names": ["이름"] }`, 요청당 1~100명. 인력별 `ok`, `dataUri` 또는 `error`, `stage`, `code` 반환
- `GET /api/personnel/photo-image-by-name?name=이름`: 인력 ID 없이 이름으로 사진 조회
- `GET /api/personnel/:id/photo-image`: 기존 ID 기반 사진 조회
- `/health`: 서버 상태

## 본문 PPT 개선

- `public/static/proposal-template.js`: 본문 전용 XML 치환·계산·검증
- 여러 텍스트 런으로 나뉜 토큰, 반복 토큰, XML 특수문자·주변 서식 처리
- 사업명·주관기관·대상사업명·기간 전달, 감리원 MD는 인력별 배정에서 합산
- 감리 일정 계획: 전체 단계 및 기술 분야 수에 따라 행 복제. 전체 기간의 월 열과 연도 병합을 재구성하고 날짜 기반 막대를 배치
- 세부 감리 일정: 일반 단계의 전체 수행활동 블록을 복제. 여러 상주/상시·검수지원 단계도 각각 별도 블록으로 표시하며 일수·공수·총계 유지
- 일정 두 장표는 각각 기존 한 장 안에 모든 단계를 표시. 페이지 추가 없음. 행 높이·셀 여백·글자 크기·문단 간격을 함께 조정하며 매우 많은 단계는 작은 글씨로 표시
- 단계 확장 후 어긋나는 표 영역의 예시 주석·도형을 제거. 상단 공수 요약표도 치환 후 원래 영역 안에 맞춤
- 제목·주관기관만 쓰는 일반 템플릿에 사업 전체 공수 경고를 전파하지 않음. 공수 플레이스홀더 또는 실제 공수표를 사용하는 장표에만 공수 경고 적용
- 예비조사·조치확인 일수는 MD로 임의 역산하지 않고 확인 필요 표시
- 조치확인 인력표의 최대 3단계·15명 제한은 별도 기능으로 이번 수정 대상이 아님
- 사진 장표의 기존 2/4/6/9인 슬롯·페이지 복제 유지
- 목차별 생성·실패·미치환 보고서 유지. 일부 목차 실패나 경고가 있어도 생성된 장표는 확인창 없이 다운로드
- 장표가 전혀 없거나 합본 자체가 실패하면 오류 표시. 다른 목차의 구형 합본으로 조용히 대체하지 않음
- RFP 공수 비교 범위를 선택하기 전에는 충족을 확정하지 않음. 인력 자격은 증빙 검토 필요
- 합본 미디어 ContentType·외부 링크 보존, 마스터 ID 충돌 방지

## 사진 조회 및 해결 이력

- 사진을 이름으로 일괄 조회하며 NAS 로그인은 요청당 한 번, 다운로드는 최대 3개 동시 실행합니다.
- `증명사진(이름).png` 직접 다운로드, 네트워크·세션 오류 한 차례 재시도
- 이름 조회 경로의 숫자 ID 라우트 충돌 수정, ID=0 인력도 이름으로 구분, TBD는 조회 제외
- NAS 인증·권한·네트워크 오류를 파일 없음으로 표시하지 않고 단계·오류 코드 보존
- PNG 시그니처 확인으로 HTTP 200 + JSON 오류를 사진으로 삽입하지 않음
- 선택 변수 `NAS_PHOTO_FOLDER`는 PC 로컬 경로가 아닌 NAS File Station 공유 경로
- 사용자가 NAS 계정 권한 문제를 해결했다고 확인했습니다. 이번 일정표 작업은 NAS 설정과 사진 엔진을 변경하지 않습니다.

## 사용 방법

1. 인력·사업 HTML을 적재하고 사업 상세 화면을 엽니다.
2. 자동화 PPT 모달에서 추가 단계·사진 구성을 선택합니다.
3. RFP 최소공수 비교 범위를 확인합니다.
4. 생성 버튼을 누르면 생성 가능한 장표를 합쳐 검토용 PPT로 바로 다운로드합니다.
5. 두 일정 장표는 단계 수가 늘어도 각각 한 장에 표시됩니다. 글자가 작아지면 확대해서 확인하세요.
6. 목차별 실패·미치환 경고, PowerPoint의 문구·사진·도식·RFP 근거를 검수합니다.

## 데이터 및 보안

- PostgreSQL: 인력·경력·사업·단계 배정·템플릿·규칙 저장
- NAS: 사진·원본 증빙자료 조회
- 신규 DB 마이그레이션 및 운영 데이터 수정 없음
- `DATABASE_URL`, `NAS_BASE_URL`, `NAS_USERNAME`, `NAS_PASSWORD`는 Railway Variables 또는 로컬 `.env`에서 관리하며 커밋하지 않습니다.
- 사진 API와 로그에 NAS 비밀번호·SID·응답 원문을 출력하지 않습니다.
- 사용자가 정상화한 DB 스키마는 변경하지 않았습니다. 저장소의 기존 스키마만으로 운영 DB를 재생성하지 마세요.

## 미완성 범위와 다음 단계

- 전체 38개 목차의 사업별 동적 작성은 완성되지 않았습니다. 미등록 템플릿 목차는 실패로 표시합니다.
- `MANPOWER_MD` 전용 양식·생성기 연결이 필요합니다. 인력 실적표를 공수표로 대체하지 않습니다.
- 조치확인 인력표의 단계/인원 확장, 조직도·비율·총괄 요건·교육·회사 실적 등의 규칙 확정 필요
- 세부 일정의 고정 수행기한·수행방안·단계별 고려사항 문구는 자동 재작성하지 않습니다.
- 전체 RFP 해석과 자격·증빙 판정은 담당자 확인이 필요합니다.
- 월별 전문 분야 막대는 배정된 단계들의 최초~최종 기간을 표시합니다. 중간 비참여 구간까지 세분화하지 않습니다.
- 템플릿 API의 Base64 일괄 로드는 유지됩니다.
- 승인된 실제 사업의 Windows PowerPoint 시각 검수가 다음 단계입니다.

## 개발 및 검증

```sh
npm ci
npm test
npm run build
```

32개 자동 테스트는 합성 데이터·메모리 PPTX·모의 NAS 응답을 사용하며 운영 DB/NAS에 접근하지 않습니다. 12단계 단일 장 생성, 추가 분야·월 열 확장, 상주/검수지원 복수 단계, 병합 셀·공수 유지, 공통 템플릿의 불필요한 공수 경고 제거를 포함합니다.

별도 읽기 전용 검증: 실제 등록된 일정 템플릿에 합성 1·6·12단계를 적용하여 6개 PPTX를 생성하고 LibreOffice PDF 렌더링을 확인했습니다. 각 결과는 1페이지이며, 12단계 세부 일정의 마지막 검수지원 행·총계와 상단 요약표가 페이지 안에 표시됩니다. 이는 Windows PowerPoint 자체의 검수를 대체하지 않습니다.

두 수행 절차 등록 템플릿에는 일부러 공수 불일치 데이터를 주입해도 제목·주관기관 치환만 수행하고 관련 없는 경고가 발생하지 않음을 확인했습니다.

## 배포

- Dockerfile이 TypeScript를 컴파일하고 정적 파일을 `dist/static`에 복사합니다.
- GitHub 연결 자동 배포가 활성화되어 있으면 푸시가 Railway 배포를 유발할 수 있습니다. 별도 승인 전 푸시하지 않습니다.
- 원본 `sweatmoon/proposal-portal` 및 원본 production DB는 변경 대상이 아닙니다.
